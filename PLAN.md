# Project Plan: Apify Actor Portfolio Website

> **Repo:** `serjii.github.io` (currently empty)  
> **Deploy:** GitHub Pages → `https://serjii.github.io`  
> **Inspiration:** [muhamed-didovic.github.io](https://muhamed-didovic.github.io) — modern dark theme, glassmorphism, gradient accents. We'll do better: cleaner cards, richer animations, more polished typography, and a proper landing page.

---

## Overview

The project has **two independent workstreams** that can happen in parallel:

| Stream | Description | Owner |
|--------|-------------|-------|
| **A — Data Pipeline** | Python script that fetches your Apify actors and writes `actors.json` | Backend / Python |
| **B — Frontend** | HTML/CSS/JS landing page that renders `actors.json` with search, filters, sort | Frontend |

The data pipeline runs once per deployment (via GitHub Actions on push to `main`).  
The frontend is a pure static site — no build step, no framework, just HTML + CSS + vanilla JS.

---

## Architecture

```
serjii.github.io/
├── actors.json            ← generated by fetch-actors.py (git-tracked)
├── fetch-actors.py        ← Python script (also runnable locally)
├── index.html             ← landing page
├── styles.css             ← design system + page styles
├── app.js                 ← client-side rendering + search/filter
├── pyproject.toml         ← project metadata + dependencies (uv-managed)
├── uv.lock                ← reproducible dependency lockfile (git-tracked)
├── .venv/                 ← uv's implicit venv (gitignored)
├── .github/workflows/fetch-actors.yml  ← CI that runs fetch-actors.py on push
├── assets/
│   ├── favicon.svg
│   └── og-image.png       ← optional, for social sharing
└── PLAN.md
```

**Why this structure?**
- `actors.json` is committed so the page works without runtime API calls (no token needed in the browser).
- The Python script can also be run locally to seed/update data.
- `uv` manages the venv and dependencies (`pyproject.toml` + `uv.lock`), no manual `pip` or `venv` setup needed.
- `.github/workflows/` keeps CI self-contained.

### T02 — `fetch-actors.py` — Apify API data pipeline

**Goal:** Python script fetches all your actors and writes `actors.json`.

**API calls required:**

1. `GET https://api.apify.com/v2/actors?my=1&limit=1000&desc=1`
   - Returns paginated list with `id`, `title`, `description`, `isPublic`, `categories`, `stats`, `modifiedAt`, `createdAt`
   - If >1000 actors, paginate through all pages
2. `GET https://api.apify.com/v2/actors/{actorId}` (optional, only if list endpoint lacks `pictureUrl`)
   - Returns `pictureUrl` (icon/logo), `seoTitle`, `seoDescription`
   - May not be needed — the list endpoint sometimes includes `pictureUrl` already

**Requirements:**
- Read `APIFY_TOKEN` from environment variable (`.env` file or `os.environ`)
- Read `APIFY_USERNAME` from env (used to build the link: `https://apify.com/{username}/{actor-name}`)
- Declare `requests` as a project dependency in `pyproject.toml` (added via `uv add requests`)
- Use `requests` library (standard for Python API consumers)
- Handle pagination: loop through `offset` values until all items are fetched
- Handle rate limiting: retry with exponential backoff on 429 responses
- Handle authentication errors (clear error message if token is missing/invalid)
- Map Apify `categories` (e.g. `DEVELOPER_TOOLS`, `OPEN_SOURCE`, `SCIENCE_AND_EDUCATION`) to human-readable labels:
  - `DEVELOPER_TOOLS` → `Developer Tools`
  - `OPEN_SOURCE` → `Open Source`
  - `SCIENCE_AND_EDUCATION` → `Science & Education`
  - `E_COMMERCE` → `E-Commerce`
  - `MARKETING` → `Marketing`
  - `SOCIAL_MEDIA` → `Social Media`
  - `FINANCE` → `Finance`
  - `HEALTH_AND_SPORTS` → `Health & Sports`
  - `TRAVEL` → `Travel`
  - `REAL_ESTATE` → `Real Estate`
  - `SHOPPING` → `Shopping`
  - `GOVERNMENT` → `Government`
  - `JUDICIAL` → `Judicial`
  - `NEWS_AND_MEDIA` → `News & Media`
  - `HUMAN_RESOURCES` → `HR & Recruitment`
  - `OTHER` → `Other`
- Output JSON format:

```json
{
  "actors": [
    {
      "id": "abc123",
      "title": "Actor Name",
      "description": "Short description",
      "category": "Real Estate",
      "isPublic": true,
      "iconUrl": "https://...",
      "link": "https://apify.com/username/actor-name",
      "stats": {
        "totalRuns": 150,
        "totalUsers": 42,
        "totalUsers30Days": 12
      },
      "createdAt": "2025-01-15T10:00:00.000Z",
      "modifiedAt": "2026-09-01T14:30:00.000Z"
    }
  ],
  "generatedAt": "2026-10-27T12:00:00.000Z"
}
```

**Deliverable:** `fetch-actors.py` produces valid `actors.json`. Test with a sample token.

### T03 — `fetch-actors.py` CI — GitHub Actions workflow

**Goal:** Every push to `main` runs the script and commits the updated `actors.json`.

**Requirements:**
- Create `.github/workflows/fetch-actors.yml`
- Triggers on: `push` to `main`, and optionally a `schedule` (e.g. weekly)
- Steps:
  1. Checkout code
  2. Set up Python 3.11+ and `uv` (`actions/setup-uv`)
  3. Install dependencies (`uv sync --frozen`)
  4. Run `uv run python fetch-actors.py`
  5. Check if `actors.json` changed; if so, commit and push
- Uses `secrets.APIFY_TOKEN` for authentication (never stored in repo)
- Commits with message: `chore: update actors.json`

**Deliverable:** Workflow runs successfully on push and updates `actors.json`.

### T04 — Design system & `styles.css`

**Goal:** A polished, modern dark theme with glassmorphism. Better than the reference site.

**Design specs:**

| Element | Decision |
|---------|----------|
| **Font** | `Outfit` (Google Fonts) — same as reference, clean & modern |
| **Background** | Dark `#0a0a0f` with two large blurred gradient orbs (one blue, one purple) fixed in corners |
| **Header** | Frosted glass (`backdrop-filter: blur(14px)`), flexbox with brand + nav links |
| **Hero** | Centered, gradient text (`linear-gradient(135deg, #3b82f6 → #8b5cf6 → #ec4899)`), large font, lede paragraph, CTA buttons |
| **Stats** | Three big numbers in gradient, centered row |
| **Filter bar** | Sticky top, glass effect, horizontal scroll on mobile |
| **Search input** | Pill-shaped, focus ring with blue glow, `/` keyboard shortcut to focus, `Escape` to clear |
| **Category chips** | Pill buttons, active state = gradient fill + shadow, show count badge |
| **Card grid** | CSS Grid, `minmax(320px, 1fr)`, auto-fill |
| **Cards** | Frosted glass bg, hover: lift (-4px) + glow shadow + gradient border reveal, icon + title + description + tech pills + status badge + CTA link |
| **Footer** | Glass effect, CTA for commissions, social links |
| **Mobile** | Break at 720px: filter bar stacks vertically, grid becomes single column, nav hides |

**CSS architecture:**
- CSS custom properties for all colors, spacing, radii, shadows
- `@import` for Outfit font
- Well-commented sections
- No framework, no build step

**Deliverable:** `styles.css` with full design system, works with `index.html`.

### T05 — `index.html` — Page structure

**Goal:** Semantic HTML5 page matching the wireframe.

**Sections (in order):**

1. **`<header class="site">`** — Top navigation
   - Brand: avatar image + "Serhii [Name]" + subtitle
   - Nav links: GitHub, Apify profile, Email

2. **`<main>`**
   
   a. **Hero section** — `<section class="hero">`
      - `<h1>` — Gradient text, e.g. "My Apify Actors"
      - `<p class="lede">` — One-line description, links to Apify profile
      - `<div class="stats">` — Three stat cards (total actors, public actors, categories)
      - `<div class="ctas">` — Two buttons: "Browse on Apify" (primary, gradient), "Commission an actor" (secondary, outlined)
   
   b. **Filter bar** — `<section class="filters">`
      - Search input with icon, clear button, keyboard hint
      - Category chips (rendered from JS based on data)
      - Sort dropdown: Newest / Oldest / Recently updated / A→Z
   
   c. **Card grid** — `<div class="grid-wrap">`
      - `<div class="grid" id="grid">` — populated by JS
      - `<p class="empty" id="empty" hidden>` — "No actors match your search."

3. **`<footer class="site">`**
   - CTA: "Need a custom actor?" + email link
   - Social links row

4. **Hidden `<svg>` sprite sheet** — inline SVG defs for icons (link arrow, search, mail)

**Accessibility:**
- Semantic HTML (`<header>`, `<main>`, `<footer>`, `<nav>`, `<section>`)
- `aria-label` on nav, filter bar
- `aria-live="polite"` on grid for screen readers
- `:focus-visible` styles for keyboard navigation

**Deliverable:** `index.html` with proper structure, accessible markup, linked to CSS/JS.

### T06 — `app.js` — Client-side rendering & interactivity

**Goal:** Fetch `actors.json`, render cards, implement search/filter/sort.

**Requirements:**

1. **Data loading**
   - `fetch('actors.json')` on DOM ready
   - Parse JSON, store in module-scoped `actors` array
   - Update hero stats with computed values
   - Render category chips dynamically from unique categories found in data

2. **Card rendering**
   - For each actor: render a `<article class="card">` with:
     - Icon: `<div class="icon">` with `<img>` if `iconUrl` exists, else fallback letter initial
     - Title: `<h2>`
     - Description: `<p class="summary">`
     - Category badge (small, subtle pill)
     - Stats row (small text: runs, users, etc.)
     - CTA: `<a>` to `link` with "View on Apify"
     - Status indicator: Public (green dot) / Private (grey dot)
   - Escape all user-controlled strings (XSS prevention)

3. **Search**
   - Debounced input (300ms) on `search` event
   - Filters by title, description, category (case-insensitive substring match)
   - Clear button appears when search has text
   - `/` key focuses search, `Escape` clears

4. **Category filter**
   - Click chip → toggle active state (single-select)
   - `activeCat === 'all'` shows everything
   - Update chip count badges after filter applied

5. **Sort**
   - `<select>` dropdown with 4 options
   - Re-sorts filtered array and re-renders grid

6. **Performance**
   - Debounce search input (300ms)
   - Re-render only when data, query, or category changes
   - Use `DocumentFragment` for batch DOM insertion

7. **Error handling**
   - If `actors.json` fails to load: show inline error message in grid area

**Deliverable:** `app.js` fully functional with search, filter, sort, and responsive rendering.

## Design Notes (How We Improve on the Reference)

| Aspect | Reference site | This site |
|--------|---------------|-----------|
| **Typography** | Good, but standard weight usage | Use variable weights (300–800), tighter letter-spacing on headings |
| **Hero** | Static gradient text | Add subtle particle or dot-matrix background animation |
| **Cards** | 3-column grid, info-dense | Spacious cards, subtle hover reveal (gradient border animation), icon with letter fallback |
| **Filter bar** | Functional | Add smooth transitions, active chip has a "magnetic" glow effect |
| **Empty state** | Plain text | Animated illustration or icon + text |
| **Loading state** | None | Skeleton cards while JSON loads |
| **Micro-interactions** | Hover lift only | Card hover: gradient border sweep, icon pulse, CTA color shift |
| **Mobile** | Basic responsive | Better mobile: collapsible nav, touch-friendly chip scroll |

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| Vanilla JS (no framework) | Zero build step, instant load, GitHub Pages compatible |
| Static JSON (not live API) | No token exposure in browser, works offline, instant renders |
| `uv` as package manager | Fast, zero-config venv management, `pyproject.toml`-native, lockfile (`uv.lock`) for reproducibility |
| `requests` for Python | Standard, lightweight, no extra dependencies |
| GitHub Actions for CI | Free, integrated with Pages, automatic on push |
| CSS custom properties | Easy theme customization, DRY |
| Outfit font | Clean, modern, great for dashboards/portfolios |
| Single-file `actors.json` | Simple, git-friendly, no database needed |
